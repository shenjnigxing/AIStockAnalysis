# R13 独立审查 05：高级投资研究经理与多资产风控

- 审查者：独立子代理 `r13_investment`，没有阅读其他角色报告。
- 日期：2026-10-21；代码基线 `c1802e6`；独立分支 `audit/r13-investment`。
- 目标：1–6个月、先行业后板块再个股择时、经营健康中市值公司、超跌/低关注的轮动研究；兼顾A股、美股、黄金、国债和期货，区分东方财富证券、东方财富期货、OKX产品。
- 审查方式：实际代码阅读、独立内存数据库服务调用及纯研究函数输入对照。没有改产品代码，没有下单，没有调用个人账户或外部行情。
- 结论：**不能验收为符合上述投资目标的完整推荐系统。** 新V3的实验与不交易标记清楚，账户目录也明确未连接；但旧推荐入口仍有未经可信度门禁的行动标签，选股资格和风险处罚存在实际漏洞。

## INV-01｜P0｜旧选股可把过期、停用且带ST名称的股票放入候选，未按资产资格或行情时效拒绝

**状态：已通过实际服务调用证实。**

证据：

- `services/screener/screener_core/screener.py:122-126` 仅从最新2000条 `RealtimeQuote` 按代码取最新，没有年龄阈值，也没有关联 `StockMaster`。
- 同文件 `:138-158` 的资格判断只有代码排除、涨幅、价格、成交额、量比和波动，缺ST/停用状态检查。
- `apps/api/app/db/models.py:9-17` 的 `StockMaster` 已有 `name`、`is_active`；当前筛选没有使用。**ST名称只是本次复现的可识别样本，生产修复应使用经时点验证的ST状态，不能只靠名称推断。**

实际复现：内存库添加 `StockMaster(symbol='600001', name='*ST示例', is_active=False)` 和 `quote_time=2000-01-01`、价格10、涨幅2%、成交额1亿的报价，调用 `ScreenerService.run({'exclude_st':True, 'min_market_cap_yi':30, 'max_market_cap_yi':300})`。

输出：`stale_inactive_ST_candidates [('600001', 72.77)]`。

影响：旧数据可以作为今天的健康股票候选继续进入推荐；`latest`只意味着库内最后一次，不能意味着仍可交易或当前有效。此问题与已修复的“最新筛选批次隔离”不同：即使最新批次本身也会选中不合格旧报价。

最小修复：旧筛选/推荐没有可信资格数据时拒绝进入候选；按市场交易日判断源时间鲜度，并关联时点正确的可交易、ST、上市/退市状态。未知状态给明确拒绝理由。

验收：过期报价、停用证券、已确认ST、资格未知四类样本均不进入候选；合格新报价可入选；响应需返回拒绝理由和分析时点。

## INV-02｜P1｜中市值健康企业与行业先行要求没有成为可执行筛选条件，未知筛选键被静默接受

**状态：实现缺口与静默忽略均已证实；不声称已从真实公司财报测出误选率。**

证据：

- `services/screener/screener_core/screener.py:128-136` 实际读取的筛选键没有流通市值、财务健康、行业、板块阶段、关注度或研究持有期。
- `apps/api/app/api/routes/screener.py:12-16` 接受任意 `dict`，未知键不报错；`filter_snapshot` 又会完整保存提交的筛选值（`screener.py:170`），形成“条件已记录”的外观。
- `apps/api/app/db/models.py:9-17` 没有流通市值、财务披露时点或行业归属历史；旧推荐上下文 `services/recommendation-engine/recommendation_core/recommendation.py:185-189` 只有市场状态、报价与日K线，行业研究结果没有绑定到股票研究。
- `screener.py:74-85` 基础分主要是当日涨幅、成交额、量能、突破；不能由此推出企业经营健康或1–6个月轮动埋伏资格。

复现：INV-01同一次真实服务调用提交的 `exclude_st`、`min_market_cap_yi`、`max_market_cap_yi` 不会被任何判断读取。该结果不证明具体股票市值多少，只证明这些提交条件没有执行。

影响：用户不能用该入口复现自己的投资约束，保存的筛选条件还可能被误认成真正执行过的约束。系统当前是若干平行实验，而非行业→板块→个股的研究链。

最小修复：先拒绝未支持筛选键，不展示“已按健康中市值筛选”的结果；逐步加入有披露时点、版本和缺失拒绝规则的市值/财务/行业输入，并把行业研究ID绑定到个股研究。

验收：未知键422；市值边界30/300/500亿元样本按用户方案明确处理；缺失财务或行业来源不得通过；个股结果能回溯到行业版本、反证和失效条件。

## INV-03｜P0｜旧推荐的 `execute` 行动标签仍绕过新V3的数据/模型门禁

**状态：代码路径和直接服务方法行为已证实；本轮未构造一个真实市场A等级推荐，未声称系统已自动下单。**

证据：

- `services/recommendation-engine/recommendation_core/recommendation.py:116-127` A等级且风险不高直接返回 `execute`，另有 `execute_with_caution`；方法没有来源、资格、PIT或模型验证参数。
- `:262-278` 生成结果时直接写行动标签和 `confidence_level`；后者由分数线性组合、裁剪至0.98，不是经校准胜率。
- `apps/api/app/api/routes/recommendation.py:14-30` 旧结果序列化包含上述行动/置信字段，但缺少数据来源等级、分析时点、模型验证状态、`can_trade=false`；`/run`（`:33-45`）没有新V3可信度门禁。
- `apps/web/app/recommendations/page.tsx:19,63-77` 仍为“推荐榜单”、等级、总分、“建议”，直接展示行动标签；`:38` 甚至仍称“启用大模型修正”，虽然上一轮已修为解释不改分。
- 相比之下 `apps/api/app/services/multi_asset_research.py:173-178` 明确输出未回测、不可交易；旧入口没有采用同一合同。

实际调用：`RecommendationService(db)._action_suggestion('A','neutral',2)` 输出 `execute`。

影响：同一产品中的新实验页和旧推荐页表达矛盾。用户可把未验证分数/启发式置信度当成可执行投资建议。当前实盘路由默认拒绝这一点是已修事实，**不消除对人工投资决策的误导**。

最小修复：旧链路先统一研究预览合同，未过资格/PIT/OOS门禁时只返回研究动作；展示数据来源、时点和验证状态；把启发式 `confidence_level` 改名或明示非概率；修正文案“修正”。

验收：非验证数据即使分数达到A级也无 `execute`；旧页面与新页的可信度状态一致，所有旧API读结果均可见门禁状态。

## INV-04｜P1｜成交量支撑不足标签在候选与推荐之间不一致，风险罚分被漏掉

**状态：真实函数对照已证实。**

证据：

- `services/screener/screener_core/screener.py:109-110` 量比小于0.75写入 `weak_volume_support`。
- `services/recommendation-engine/recommendation_core/recommendation.py:50-52` 只识别 `weak_volume` 才加6分风险。
- 候选风险确实会并入最终标签（`:213-219`），但没有规范化/映射。

实际输出（中性市场）：

```text
_risk_from_tags(['weak_volume_support'], 'neutral') -> (2.0, [])
_risk_from_tags(['weak_volume'], 'neutral')         -> (8.0, ['成交量支撑偏弱'])
```

影响：推荐会显示弱量风险标签，但未落实相应风险分和反证；0.60–0.75量比区间不能指望策略层另一个阈值补上。是否实际跨A/B等级需依具体样本，不夸大为所有股票都会跨级。

最小修复：风险标签统一枚举/合同，所有来源的同类标签归一化；未知标签要明确为未计分而非默默丢弃。

验收：候选→推荐完整管线测试同一弱量样本产生6分增量风险、对应解释，且不重复计罚。

## INV-05｜P1｜期货保证金比例被当作单调风险指标，低保证金样本反而更容易被列为 inspect

**状态：对照输入行为已证实；属于风险模型定义缺陷，不把实验分数说成真实账户杠杆或真实爆仓概率。**

证据：

- `apps/api/app/api/routes/research_v3.py:35-37,61` 期货只要求到期日、乘数、保证金比例，没有头寸数量、权益、结算价、维持保证金或压力损失。
- `apps/api/app/services/multi_asset_research.py:102-111` `margin_ratio > .2` 才阻断；罚分为 `min(24, margin_ratio*75)`，比例越低罚分越少。合约乘数未参与风险金额计算。
- 同文件 `:149-151` 非阻断且分数≥70可成为 `inspect`，而不是“杠杆/头寸风险未知”。

真实对照：同一条121点、每日+0.1%的**人工构造**价格序列，`IF2612`、到期日2026-12-18、乘数300，仅修改保证金比例：

```text
margin 0.01 -> experimental / score 72.04 / blocks []
margin 0.30 -> blocked / score None / ['该期货保证金比例较高，当前实验不做推荐']
```

影响：保证金比例不能单独代表总风险；当前对比会让低保证金看起来更安全，但系统根本没有账户权益/名义敞口模型。现有“未计入真实成本”“不可交易”标记降低误用风险，却不能使这一资产风险排序合理。

最小修复：在未实现头寸、权益、波动压力、维持保证金和流动性模型前，把期货风险列为未知/阻断，不给风险调整后的 inspect；后续分开“保证金占用”和“价格敏感敞口/杠杆”。

验收：缺账户风险必要字段时无 inspect；在头寸/权益固定或保证金投入固定的明示情景下，分别验证损失与杠杆敏感度，不以保证金比例高低直接判安全。
