## 结论与证据边界

**不接受当前快照作为完整可信推荐系统。** 194项既有测试再次通过，但定向反例仍证实账务、数据资格、测试隔离和请求状态问题。此前Windows/Chromium云验收通过仍成立；它证明所测启动和成功路径，不证明所有数值正确或所有功能完成。

主线程于2026-10-26在内存库重跑了量化、数据和旧推荐门禁探针，以及抽取真实前端处理函数的Node探针。复现脚本在 [repro](repro/)；全部是人工夹具，不是市场回测或真实行情成功记录。Python探针拒绝持久数据库URL，严禁把复现脚本指向个人业务库。`pytest`复跑也显式使用内存库。

Docker与升级旧schema的部分结论属于配置/模拟证据，不能写成用户机器已发生故障；浏览器CSRF完整利用仍有浏览器访问策略等前提。每份原始报告保留证据等级和未覆盖范围。

## 修复与复审顺序

1. 先处理G01–G04和S01–S03，冻结不可信推荐输出、保护业务数据。
2. 修复数据身份/单位/增量、回测成交账务与参数，再补能失败的回归断言。
3. 修复前端请求状态、部署与运维一致性；完成行业到个股、证据/反证、观察池和复盘真实任务。
4. 每工作包分配实现者与独立复审者，原始发现保留；修复后记录新提交、反例变为拒绝/正确值、回归与剩余限制，再决定验收。
