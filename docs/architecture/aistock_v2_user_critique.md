# AIStock V2 — 第一轮产品交付后的用户批判与第二轮改进

> 评审对象：首次建立的 v2 研究工作台、评分内核、只读 API、JSON 实验室。
> 评审身份：假设我是每周筛选 1–6 个月 A 股投资机会的个人用户，而不是系统开发者。
> 结论：**第一轮可以称作“技术验证”，不能称作“可用于实际选股的成品”。**

## 真实用户任务挑战

1. **我打开首页，能否直接知道本周哪些行业开始改善？** 不行。首页目前能告诉我系统能力、研究路径和旧版候选，但没有由生产数据生成的可信行业名单。【P1 阻断】
2. **我不懂 JSON，能不能快速试用算法？** 第一轮不能；把样本数据放在代码框里会逼用户理解后端协议。【第二轮已修：默认单股引导表单，JSON 留作高级批量工具】
3. **我看到 83 分，是不是成功率 83%？** 第一轮没有足够醒目的解释，容易导致误解。【第二轮已修：score 是假设评分，证据等级标记 manual_unverified，模型未回测；改称优先核查而非执行】
4. **这只股票为什么优先？来自哪个行业？** 第一轮仅有单股因子。【第二轮部分修：加入按行业汇总的样本内分数、样本数及样本不足状态；真正行业优先的统计模型需 P2】
5. **我能否用股票代码一键取到财报和上市状态，完全不手工填 13 个指标？** 仍然不行。手工输入不能证明财务口径、披露时间以及是否复权。【P1 阻断】
6. **回测是不是告诉我策略真的有优势？** 不行，只有原项目的回测框架和未验证的规则分，不存在可信的样本外收益证据。【P2 阻断】
7. **在市场极弱时，会不会误导我追涨？** V2 弱势只给观察研究，不返回交易指令；旧版交易与原评分路径仍在，需要隔离并做安全审查。【已降低 V2 风险；P4 阻断】
8. **系统今天没拉到数据，会不会仍推荐股票？** V2 样本缺数据时会 fail-closed，首页旧版候选也明确标为旧版；但原数据层是否对所有缺失场景严格失败，尚需迁移与全链路测试。【P1 阻断】

## 需求闭环：每次改完必须重复

```text
交付 Vn 的可运行代码
  -> 从真实用户任务逆向测试（能否完成 / 是否被误导）
  -> 记录严重性和证据
  -> 修复可落地项 + 明示未修复阻断项
  -> 同一套数据重测 + 旧功能回归
  -> 出具 Vn+1 验收结论，继续迭代
```

## 本轮实际修改记录

| 反馈 | 原问题 | 第二轮修复 | 当前局限 |
|---|---|---|---|
| 使用门槛太高 | 必须先编辑 JSON | 默认字段化表单、分组显示、示例输入 | 仍需人工提供数据 |
| 分数容易被误解 | 高分像推荐执行依据 | `verify_first` + 模型未验证 + 来源未验证 + 只读隔离 | 需要 OOS 研究证据 |
| 行业视角不足 | 只有单股评分 | `sector_overview` + 样本量与覆盖标记 | 非全市场行业轮动 |
| 财报时间不足 | 只检查未来披露 | 披露日期超 210 日则拒绝研究评分 | 财报更正公告仍需 PIT 数据存储 |
| 结果不透明 | 无权重贡献 | `score_components` 和 `penalty_points` | 权重仍然是人工假设 |
| 界面功能太散 | “官方门户”导航拥挤 | 研究优先侧边导航、系统状态卡、研究路径 | 需真机可用性测试 |

## 第二轮后的继续批判（未过关事项）

**致命级：** 当前系统没有经独立核实的点位数据源与样本外策略表现。因此不允许称为“已完成智能选股重构”，也不允许展示现实股票推荐成绩。

**重要级：** 缺少行业优先的独立板块模型、统一基准、历史股票池、风险归因、比较多个算法的实验管理和成本敏感回测；要按 P1/P2 优先级补齐。

**用户体验：** 单股表单仍要求填写大量量化指标，普通用户每天不会这么做。下一步必须以“一键更新数据 → 浏览行业 → 查看候选与反证”为默认路径，把手工输入降为开发者模式。移动端导航仍需真实设备确认。

**工程验证：** 当前变更经 GitHub API 提交，没有在本会话运行完整 Python/Node/Playwright 集成测试；只有测试代码。禁止将“已提交测试文件”表述为“测试全部通过”。

## 发布门槛

任意一个阻断仍存在时，产品只能标注为 **Research Preview / 非生产级**。每个后续迭代必须包含本文件的更新、一次负面用户审查、修复证据和回归测试结果。
