# QA-006: 真实浏览器截图复审与二次视觉修复

日期：2026-10-21。来源：GitHub Actions run 39529029150 / Chromium Playwright，1280px 桌面、375px 手机，实际下载并目视检查截图；见 Actions artifact `sector-research-visual-evidence`。这是前端合成样本 + API mock 的浏览器测试，不是生产行情或真实交易验证。

## 审计实证

**桌面（1280px）初版**
- ✅ 导航、研究目标、两套模型、数据可信度说明、显式合成演示、因子解释具备完整层级。
- ❌ P1：左侧行业表格设置固定最小宽度 600px，但桌面布局下表格卡实际可视区域更窄；“研究强度”这一最重要的末列被水平滚动隐藏。默认整页截图无法看到该列，会直接影响投资者的排序判断。
- ❌ P2：左右两列 CSS Grid 默认 stretch，左侧只有两行测试数据却被右侧较长的因子卡片拉到同样高度，出现大片空白。

**手机（375px）初版**
- ✅ 空结果、来源警告、两套模型选择、手动加载演示均完整可见；无页面级水平滚动。
- ⚠️ 移动端横向导航需要手指滑动，初次用户可能遗漏后续菜单项；当前优先核心入口，后续可做折叠菜单和独立搜索。
- ⚠️ 操作区纵向滚动偏长，但数据可信度声明优先于空结果；不为了压短页面删除警示。

## 已对具体缺陷做二次修正
- 在桌面取消表格 `min-width:600px`，微调单元格 padding，保留手机端内部横向表格滚动。
- 加 `align-items:start` 防止左表格卡片因右卡高度而强行拉伸。
- Playwright 新增断言：桌面“研究强度”列必须 100% 处于 viewport 可视范围内。浏览器门禁失败就不能宣称 UI 通过。
- 截图持续通过 Actions artifacts 保存，支持后续有证据的视觉对照。

## 重要区别
- 真实 Chromium 跑通的是前端 UI mock 路由和可访问性 /交互检查；FastAPI 领域测试通过属于另一个 CI job。
- API/mock 证据不能代替真实源数据的时点验证；截图也不能证明模型对实际 A 股有优势。
- 未执行 1920px 多显示器、低对比度辅助功能、屏幕阅读器和真实用户访谈。这些不是已通过验收。

## 下一轮要挑的产品问题
1. 用户仍需自己粘贴或构造行业指数价格序列；本轮只适合模型实验，不适合每日一键选股。
2. “前期低关注”“资金回流”不是单凭价格相对收益就能证明，应补公告 PIT、行业景气和风险暴露。
3. 两套模型当前只是人工权重，不能混淆回测 IC/Sharpe 或概率。
4. 看似专业的高分一旦接上真实数据，会引诱用户直接买卖；生产版本必须引入模型有效期、样本外失败门槛、持仓约束和负面论证。
5. 首页存在旧版评分入口，需正式 UX 与数据迁移计划，避免真实/模拟混用。
