# R14 研究工作台与交互修复

## 设计与最终行为

以 Koyfin 多面板研究工作台、TradingView 分组观察表、Finviz 行业比较的信息组织方式为参考，独立实现深色 navy/slate 终端，不复制其品牌或具体页面。

- 官方参考：https://www.koyfin.com/features/custom-dashboards/ 、https://www.koyfin.com/features/watchlists/ 、https://www.tradingview.com/support/solutions/43000745825-mastering-the-tradingview-watchlists/ 、https://finviz.com/groups 。这些参考不代表本项目已经拥有其行情授权、金融指标或全部功能。
- `/research` 从介绍性大标题页改为日常研究工作台：市场和周期切换、数据覆盖卡、行业观察分类、可检索排序观察表、候选资格、数据源失败状态、右侧标的快照、证据/风险、持久研究论点编辑器及研究路径。
- 所有价格来自缓存查询；无价格时显示明确空态，不编造K线、热图、胜率或收益。仅存在一个快照时不画虚假趋势图。
- 观察池实际调用 GET/POST/PATCH/DELETE `/api/research/v3/watchlist`，保存论点、反证与失效条件到服务器；失败不展示成功，成功回填记录ID再编辑。市场、周期、行业、检索条件联动真实已保存笔记，行业分类不是捏造实际行业指数。
- 旧推荐仅在A股上下文展示迁移对照，门禁失败显示阻断；正式推荐资格并未被UI擅自提升。

## 审查条目修复

- F01：行情页与工作台使用请求序号及返回kind/symbol检查，切换标的使旧响应失效；编辑代码立即清除旧报价。
- F02：共用动作表单使用同步ref锁和network pending覆盖整个请求，连续点击不会重发；捕获网络/解析异常并清空旧成功结果，提示结果未知时先核对，不自动重试。
- F03：快照查询成功后重新读取数据源诊断；工作台提供显式刷新。
- U01：行业实验可携带行业和source_grade进入工作台，明确合成行业不是实际成分股；观察池行业按钮筛选真实已保存研究记录。
- U02：个股详情展示理由、反证、风险与解释，缺来源/分析日期显示缺失，null置信度显示未校准。
- U03：使用主线程持久观察池API，不以浏览器内存或采集JSON代替长期记录。
- U04：复盘快捷筛选合并已有query，清空筛选仍是显式操作。

- Next 15 生产构建通过；仅存在工作区多lockfile与旧CSS警告。

- 本地没有可用Chromium；浏览器用例及最终视觉截图需主线程/CI执行，不能把构建通过等同视觉验收。

## 限制

当前工作台没有完整历史序列API，因此不画实时K线；没有真实行业成分和财务API，因此行业上下文只作为研究标记、资格缺口明确。账户仍未连接。视觉密度提高不改变任何数据和投资门禁。
